阅读来源：`lab1/cpu设计指导书和指导书仓库-实验1（来自github）.zip` 内 `docs/` 全部 Markdown 章节。

当前落地对象：`miniRV`、`EGO1` 模板工程；用户确认 A/B 两组均由本人完成，因此实验一目标是 A 组 18 条 + B 组 18 条，共 36 条指令，并保持模板已实现 8 条指令不回退。

## 1. 实验一总体要求

实验目标是理解并实现单周期 CPU，熟悉 miniRV 指令集，掌握“数据通路 + 控制器 + 模块化 Verilog + Trace 验证”的完整流程。

实验一主线要求：

1. 下载数据通路表、控制信号表模板，以及对应开发板/指令集的 Vivado demo 工程。
2. 先运行 demo 仿真，结合波形、数据通路表和示例代码理解模板。
3. 分别完成 A/B 组指令的数据通路表和控制信号表。
4. 整合完整单周期 CPU 数据通路图。
5. 按模块划分，为每个模块新建 `.v` 源文件或补全已有模块，用 Verilog 实现内部逻辑。
6. 分别通过 A/B 组 Basic Trace 调试验证。
7. 整合完整 CPU，通过完整 Basic Trace。

对我们当前任务的含义：不能只“补几个 case”，应先保证表格、控制信号、模块边界和验证路径闭环。

## 2. 指令与当前范围

miniRV 是 RV32I 子集，指导书列出 37 条 miniRV 指令。模板工程已经实现 8 条示例指令：

`addi`、`ori`、`slli`、`lui`、`lw`、`beq`、`bne`、`jal`

本次 A/B 组合计 36 条目标指令，按用户材料为：

- A 组：`sll`、`srl`、`srli`、`sra`、`srai`、`add`、`sub`、`auipc`、`xor`、`xori`、`lb`、`lbu`、`lh`、`lhu`、`sw`、`sb`、`sh`、`jalr`
- B 组：`mul`、`mulh`、`mulhu`、`div`、`divu`、`rem`、`remu`、`or`、`and`、`andi`、`blt`、`bge`、`bltu`、`bgeu`、`slt`、`slti`、`sltu`、`sltiu`

注意：`docs/lab1/13-trap.md` 的异常/中断、CSR、`csrrwi/mret/ecall` 属于扩展方向，不是当前 36 条 A/B 指令主线。

## 3. 模板工程与接口时序

模板工程是可继续开发的 demo，已包含 CPU 顶层、取指接口、数据访存接口、IROM/DRAM、RF、ALU、控制器、立即数扩展、访存请求与访存数据扩展等基本模块。

CPU 对外有两类接口：

- 取指接口：`ifetch_req`、`ifetch_addr`、`ifetch_valid`、`ifetch_inst`
- 数据访存接口：`daccess_ren`、`daccess_addr`、`daccess_rvalid`、`daccess_rdata`、`daccess_wen`、`daccess_wdata`、`daccess_wresp`

关键时序：

- `ifetch_req` 只有效 1 个时钟周期。
- `ifetch_valid` 只有效 1 个时钟周期，只有它有效时 `ifetch_inst` 和译码信号才可信。
- Load 发出读请求后，需要等待 `daccess_rvalid`。
- Store 发出写请求后，需要等待 `daccess_wresp`。
- Block Memory 读一般是发地址后一拍返回数据；写在同一时钟沿接收地址、写使能和写数据。

当前实现时要尊重模板的多周期等待框架，不能把 Load/Store、Mul/Div 当成普通单周期组合结果。

## 4. 数据通路与控制器方法

指导书采用“表格驱动设计”：

- 先按每条指令推演需要哪些部件、每个部件输入来自哪里、输出去哪里。
- 再把所有指令的数据通路综合到一行“综合”数据通路。
- 对多输入来源增加多路选择器，或扩展模块输入，例如 SEXT 接收可能构成立即数的多个字段。
- 在综合数据通路下方补“操作选择信号”和“多路选择信号”。
- 控制器根据 `opcode/funct3/funct7` 产生控制信号。

控制信号分两类：

- 操作选择信号：控制 NPC、SEXT、ALU、MREQ、MEXT、RF 等模块具体执行什么功能。
- 多路选择信号：选择 ALU 输入、RF 写回数据、NPC 来源等。

指导书建议控制信号表中用可读符号，如 `PC4`、`ADD`、`WB_ALU`，实现时用 `.vh` 宏定义承接。

## 5. 关键模块要点

PC/NPC：

- 顺序执行为 `PC + 4`。
- 条件分支根据 ALU/比较结果决定是否 `PC + offset`。
- `jal` 使用 `PC + offset`，写回 `PC + 4`。
- `jalr` 需要以 `rs1 + imm` 作为跳转目标，并按 RISC-V 规则清低位；当前模板 NPC 只有 `pc + offset` 风格，后续实现需要扩展。

SEXT：

- miniRV 所有立即数均按符号扩展。
- 当前目标需要覆盖 I、S、B、U、J 类型；模板已有 I/B/U/J，S 型需要补。

ALU：

- 普通加减、逻辑、移位、比较可使用 Verilog 运算符。
- 移位位数只取低 5 位。
- 算术右移和有符号比较需要使用 `$signed`。
- 乘除法不能使用 `*`、`/` 运算符，不能使用现成 IP。

MREQ：

- Load 时 `ren=4'hF`，地址需要从 CPU 字节地址转换到存储器字地址。
- Store 需要根据地址低两位产生 `wen` 和对齐后的 `wdata`。
- `sb` 支持四种字节偏移。
- `sh` 只允许偏移 `00` 或 `10`；偏移 `01/11` 不对齐，不应发访存请求。
- `sw` 只允许偏移 `00`；否则不应发访存请求。

MEXT：

- 根据地址低两位从 32 位读回数据中选出 byte/half/word。
- `lb/lh` 符号扩展，`lbu/lhu` 零扩展。
- `lh/lhu/lw` 需要处理对齐要求；不对齐时不应发出有效访存。

RF 写回：

- ALU 类写回 ALU 结果。
- Load 类写回 MEXT 扩展结果。
- `jal/jalr` 写回 `PC + 4`。
- `lui` 写回 U 型立即数，`auipc` 写回 `PC + U-imm`。

## 6. 多周期指令约束

指导书明确：本课程虽然称单周期 CPU，但访存指令和乘除法指令是特殊多周期指令。

原因：

- 指令机器码和译码控制信号只在 `ifetch_valid` 有效的那一个时钟周期可信。
- 访存、乘除法无法在一个时钟内完成。

因此必须寄存必要信息：

- 目标寄存器号 `rd`
- 访存地址
- Load 的扩展类型
- 乘除法的 ALU 操作类型
- 必要的写回选择或操作状态

完成条件：

- Load/Store：`daccess_rvalid` 或 `daccess_wresp`
- Mul/Div：乘除法器 `busy` 从有效变为无效，且 CPU 内部仍处于乘除法等待状态

## 7. 乘除法实现要点

硬性要求：

- 自行实现硬件乘法器和除法器。
- 不得使用 `*`、`/` 运算符。
- 不得使用现成 IP 核。

统一接口时序：

- `start` 有效 1 个时钟周期表示开始运算。
- 运算过程中 `busy=1`。
- `busy` 从 1 变 0 时结果有效。

乘法：

- 指导书建议使用已学过的 Booth 补码乘法器。
- `mul/mulh` 使用有符号乘法路径。
- `mulhu` 是无符号乘法，指导书建议扩成 33 位并在最高位补 0。

除法：

- 指导书要求先在 `div_test` 工程中实现并仿真，再集成到 CPU。
- 推荐原码除法器，可采用恢复余数法或加减交替法。
- 有符号除法先将负数转为原码/绝对值参与运算，商符号由被除数和除数符号异或得到，余数符号与被除数一致。
- 除法器内部通常需要寄存器、加法器、移位器、计数器和控制逻辑。

## 8. Trace 验证要点

Trace 测试使用 Linux 环境，课程提供 WSL2、远程实验平台、自行部署三种方式。当前实验一主要使用 Basic Trace。

使用流程：

1. 将 Vivado 工程 `src/rtl` 下的所有 HDL 源文件复制到 `cdp-tests/mySoC`。
2. 不复制 `ip` 文件夹，不复制 IP 核相关文件。
3. 保持 `miniRV_SoC -> cpu_top -> cpu_core` 结构、模块名、实例名和 `cpu_core` 接口不变。
4. 不修改 `RUN_TRACE` 宏相关代码。
5. 不删除或修改 `/* verilator public */` 注释。
6. 在 Trace 框架中 SoC 顶层复位 `fpga_rst` 是高电平复位。
7. 复位后首条指令地址为 `0x00000000`。
8. 运行 `make` 编译，再用 `make run TEST=xxx` 单测，最后用 `python3 run_all_tests.py` 批测。

Trace 依赖两组调试信号：

- `debug_wb_*`：写回寄存器信息
- `debug_mem_*`：写访存信息

要求：同一条指令对应的 Trace 信号只能有效一个时钟周期，尤其是 `debug_wb_rf_we` 和 `debug_mem_we`。

调试方法：

- 出错时看 Trace 输出的 reference/mycpu 差异。
- 到 `asm/*.dump` 根据 PC 定位指令。
- 到 `waveform/*.vcd` 用 Surfer/GTKWave 看波形。
- 修改 HDL 后重新 `make` 并重跑对应测试。

## 9. Verilog 代码规范

指导书给出明确 RTL 规范，后续实现需要遵守：

- 一个 `.v` 文件只定义一个 module，module 名与文件名一致。
- 每个模块加 ``timescale 1ns / 1ps`。
- `wire/reg/input/output` 使用小写命名；`parameter/localparam/宏` 使用大写命名。
- 输入建议 `_i` 后缀，输出建议 `_o` 后缀；时钟前缀 `clk`，复位前缀 `rst`，低有效信号加 `n`。
- 向量位序降序定义，最低位为 0。
- 模块实例名使用 `U_xx_x` 风格，采用命名端口连接。
- 常量必须标注位宽。
- 组合逻辑用 `always @(*)` 和阻塞赋值 `=`，必须有完整 `else/default`。
- 时序逻辑使用单时钟、同一边沿，非阻塞赋值 `<=`。
- 不使用 `initial` 或声明初始化，初始化靠 reset。
- 尽量避免 `for/repeat/while` 和 `integer`。
- 避免多驱动、端口悬空、位宽不匹配、顶层接口出现 `X/Z`。
- 顶层输出信号必须寄存。

## 11. 常见风险清单

实现阶段尤其要盯住这些点：

- 宏定义文件需要在使用处 `include`，引用时使用反引号。
- 移位位数超过 32 或为负时，实际只应取低 5 位。
- Load 读到 0 时，优先检查字节地址/字地址转换和 Store 是否写错。
- Critical Warning 涉及时钟时，检查是否混用上升沿和下降沿。
- Trace 全部 Time out 时，优先查复位、PC 初值、取指请求、模块名/接口是否被改坏。
- Reference PC 和 MyCPU PC 不一致时，重点查分支跳转、`jal/jalr`、PC 更新时序。
- 仿真通过但下板失败时，先查 bit 文件、仿真结果、Timing Summary、Warning、RTL 规范，再考虑在线调试。
