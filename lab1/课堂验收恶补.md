## 2. 一分钟背诵版

我做的是 miniRV 单周期 CPU，在 EGO1 模板工程上补完 A 组和 B 组共 36 条指令。整体结构保持 `miniRV_SoC -> cpu_top -> cpu_core`，核心模块包括 `PC/NPC/Controller/RF/SEXT/ALU/MREQ/MEXT`，乘除法单独用多周期 `multiplier/divider` 实现。

普通 ALU、分支、跳转大部分在取到指令的同一拍完成；Load/Store 和乘除法不是严格一拍完成，所以 `cpu_core` 里用了 `ld_st_flag` 和 `mul_div_flag` 保存多周期状态，等 `daccess_rvalid/daccess_wresp` 或乘除法 `busy` 拉低后再写回寄存器并取下一条指令。

验证分三层：静态脚本检查关键接线和禁止项；算法脚本检查乘除边界；最后用 Vivado 行为仿真和 Linux Basic Trace 跑功能测试。现在新版 `cdp-tests` 的 `start` 综合测试也通过，数码管值到 `0x25000025`，表示 37 个测试点全通过。

## 5. 你要会解释的模块

### cpu_core

`cpu_core` 是 CPU 主体，把取指、译码、执行、访存、写回串起来。它不是流水线，而是用控制信号和状态位协调一条指令什么时候完成。

关键点：

- `ifetch_req` 在复位后第一次取指，或上一条指令完成后取下一条。
- `inst = ifetch_valid ? ifetch_inst : 32'h13`，没有有效指令时喂 NOP，避免错误译码。
- `ld_st_flag` 表示当前正在等 Load/Store 完成。
- `mul_div_flag` 表示当前正在等乘除法完成。
- `rf_we1` 控制什么时候真正写回寄存器。
- Trace 信号保留 `/* verilator public */`，供 Basic Trace 对比。

### Controller

`Controller` 根据 `opcode/funct3/funct7` 识别指令，产生控制信号：

- `npc_op`：PC+4、branch、jal、jalr。
- `sext_op`：I/S/B/U/J 立即数。
- `alu_op`：ALU 做什么运算。
- `alua_sel/alub_sel`：ALU 输入选 PC、rs1、rs2 或立即数。
- `ram_r_op/ram_w_op`：Load/Store 类型。
- `rf_we/rf_wsel`：是否写寄存器，写回 ALU/RAM/PC+4/立即数。

### NPC

`NPC` 算下一条 PC：

- 普通指令：`pc + 4`
- 分支：条件成立就 `pc + offset`，否则 `pc + 4`
- `jal`：`pc + offset`
- `jalr`：`(rs1 + imm) & 0xfffffffe`，最低位清零

### SEXT

`SEXT` 做立即数扩展，支持 I/S/B/U/J 五种格式。比如 Store 用 S 型，Branch 用 B 型，`jal` 用 J 型，`lui/auipc` 用 U 型。

### ALU

`ALU` 负责普通算术逻辑、比较分支、乘除法结果选择：

- 加减、与或异或、移位、比较用组合逻辑。
- 有符号比较和算术右移用 `$signed`。
- 乘除法不直接用 `*` 或 `/` 做最终硬件，而是实例化 `multiplier` 和 `divider`。
- 有符号除法在 ALU 外围做绝对值转换、符号恢复、除零和溢出处理。

### MREQ/MEXT

`MREQ` 负责把 CPU 的访存语义转成 RAM 读写使能：

- `sb` 根据地址低两位产生一个字节写使能。
- `sh` 只允许半字对齐，偏移 0 或 2。
- `sw` 只允许 word 对齐。
- Load 用 `da_ren` 发读请求。

`MEXT` 负责把读回来的 32 位数据按地址偏移取 byte/half/word，并做符号扩展或零扩展。

### multiplier/divider

`multiplier` 是多周期 Booth 乘法器：

- `start` 拉高一拍启动。
- `busy=1` 表示正在算。
- 完成后 `busy=0`，结果在 `z`。
- `mul/mulh` 用 32 位有符号路径，`mulhu` 用 33 位补 0 路径。

`divider` 是多周期恢复除法器：

- 同样是 `start/busy/result` 协议。
- `div/divu/rem/remu` 都复用它。
- 除零、`-2^31 / -1` 这种特殊情况由 ALU 按 RISC-V 语义处理。

## 8. 高频问答

### 1. 你实现了哪些指令？

A 组 18 条和 B 组 18 条，共 36 条；再加模板已有 8 条保持不退化。A 组主要是移位、加减、跳转、Load/Store；B 组主要是乘除法、逻辑、比较和分支。

### 2. 为什么还叫单周期 CPU，却有多周期？

指导书里说明访存和乘除法是特殊多周期。普通 ALU 指令取到指令后同一拍完成；Load/Store 要等 RAM 响应；乘除法要等迭代模块 `busy` 结束。

### 3. Load 怎么写回？

Load 发出读请求后，等 `daccess_rvalid`。读回的数据进 `MEXT`，按 byte/half/word 和符号/零扩展生成 `ram_ext`，然后写回 `rd`。

### 4. Store 怎么处理字节偏移？

`MREQ` 根据地址低两位生成 `da_wen` 和移位后的 `da_wdata`。`sb` 支持 0/1/2/3 四种偏移；`sh` 只支持 0/2；`sw` 只支持 0。

### 5. 为什么 `debug_mem_wdata` 用 `store_wdata_r`？

Trace 对比希望看到原始寄存器写数据，而实际 RAM 写入需要按 byte/half 做移位。两者语义不同，所以缓存原始 `rs2` 值给 Trace。

### 6. `jalr` 为什么要清最低位？

RISC-V 规定 `jalr` 目标地址是 `rs1 + imm` 后最低位清 0，所以 NPC 里用了 `(base + offset) & 32'hffff_fffe`。

### 7. 分支由谁判断？

ALU 根据 `ALU_EQ/NE/LT/GE/LTU/GEU` 输出 `br`，NPC 根据 `br` 决定走 `pc + offset` 还是 `pc + 4`。

### 8. 立即数在哪里处理？

`SEXT.v`，根据 `sext_op` 生成 I/S/B/U/J 五种立即数。

### 9. 控制信号从哪里来？

`Controller.v` 用 `opcode/funct3/funct7` 译码，产生 NPC、SEXT、ALU、RAM、RF 写回相关控制信号。

### 10. 乘法器怎么做的？

用 Booth 迭代乘法。启动后每拍处理一位，`busy` 表示还在计算，完成后输出 64 位乘积。`mul` 取低 32 位，`mulh` 取高 32 位，`mulhu` 用 33 位无符号补 0 路径。

### 11. 除法器怎么做的？

用恢复除法迭代。无符号核心输出商和余数；有符号除法先取绝对值，最后恢复商和余数符号。除零和溢出按 RISC-V 规则在 ALU 里处理。

### 12. 怎么证明没用 `*`、`/`？

可以打开 `multiplier.v` 和 `divider.v`，乘法器用加减移位迭代，除法器用比较、减法和移位迭代。静态检查脚本也检查了乘除模块。

### 13. Trace 是怎么验证的？

Trace 框架让 golden model 和我的 CPU 执行同一个 `.bin`，实时比较写回寄存器和写访存信号。只要 PC、写使能、写寄存器/写内存地址和值不一致，就停止报错。

### 14. 为什么 Trace 需要 `/* verilator public */`？

Verilator 需要访问内部 debug 信号，Trace 框架通过这些信号拿到 CPU 的写回和访存行为。所以这些注释不能删。

### 15. `start` 之前为什么失败？

不是 RTL 问题。旧版 `cdp-tests` 的 golden model 里 Digit 外设地址和 `start.bin` 实际访问地址不一致。更新到最新 `cdp-tests` 后，Digit 基址是 `0xffff2000`，`start` 已通过。

### 16. `0x25000025` 是什么意思？

高字节 `0x25` 是十进制 37，表示总测试点 37 个；低字节 `0x25` 也是 37，表示 37 个全通过。

### 17. Timing 为什么是 NA？

Vivado 的 Timing Summary 显示 WNS/TNS 为 NA，但底部显示 `All user specified timing constraints are met.`。所以不要说具体 slack 数值，只说当前用户指定约束下没有时序违例。
