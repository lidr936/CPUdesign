## 2. 核心概念讲解

### 2.1 单周期 CPU 在做什么

一条指令在单周期 CPU 中从开始到结束都在一个时钟周期内完成。可以把过程分为五个逻辑阶段：

1. **IF（取指）**：PC 给出指令地址，指令存储器输出当前 `inst`。
2. **ID（译码/读寄存器）**：Controller 识别指令编码；RF 读出源寄存器；SEXT/EXT 生成立即数。
3. **EX（执行）**：ALU 做加减、逻辑运算、比较或地址计算。
4. **MEM（访存）**：`lw` 等读数据存储器，`sw` 等向数据存储器写数据；不访存的指令直接跳过这一功能。
5. **WB（写回）**：把 ALU 结果、读出的内存数据、扩展立即数或 `PC+4` 写回目的寄存器。

并不是每条指令都真正使用五个阶段。例如 `beq` 不写回寄存器也不读写数据存储器，`lui` 不需要 ALU，`jal` 要写回 `PC+4`。作业的工作就是把这些不同情况准确地画出来并统一到一套硬件中。

### 2.2 数据通路是什么

数据通路就是 **功能部件 + 连线**。它回答的问题是：“执行这条指令时，数据从哪里来、经过哪些部件、最后写到哪里？”

以 `lw rd, offset(rs1)` 为例：

```text
rs1 --RF--> ALU.A
offset --SEXT--> ALU.B
ALU.C（地址）--> Data RAM --> MEXT --> RF.wD（写入 rd）
```

同时 PC 正常走 `PC + 4`。所以模板中 `lw` 需要：寄存器读端口、I 型立即数扩展、ALU 加法、数据存储器读、MEXT 和寄存器写回。

再看 `beq rs1, rs2, offset`：

```text
rs1 --RF--> ALU.A
rs2 --RF--> ALU.B
ALU.br --> NPC.br
offset --SEXT--> NPC.offset
NPC --> PC
```

它不产生通用计算结果，因此没有 RF 写回；ALU 的作用是产生“相等/不相等”等分支判断结果，NPC 根据该结果选择 `PC+4` 或 `PC+offset`。

### 2.3 “构造”与“综合”分别是什么

- **构造数据通路**：对一条指令填写一行。行内每个格子写“哪个信号接到当前部件输入”。
- **综合数据通路**：把所有指令行叠加，列出一个输入端可能收到的全部来源，并加多路选择器。例如 `RF.wD` 在不同指令中可能来自 `ALU.C`、`MEXT.ext`、`SEXT.ext` 或 `NPC.pc4`，因此需要 `rf_wsel` 控制的写回多路选择器。

可以把它理解成：先给每条指令画一条专用路线，再把所有路线合成一张可复用的道路网。

### 2.4 控制信号是什么

数据通路只提供“可选的路”，控制信号决定当前指令实际走哪条路、部件具体执行什么操作。

| 例子 | 没有控制时的歧义 | 由什么信号决定 |
| --- | --- | --- |
| ALU 的 B 输入 | 是第二个寄存器，还是立即数？ | `alub_sel` |
| 寄存器写回数据 | 是 ALU 结果、内存数据、立即数，还是 `PC+4`？ | `rf_wsel` |
| ALU 具体动作 | 加法、或、比较相等，还是移位？ | `alu_op` |
| 下一条 PC | `PC+4`、分支目标，还是跳转目标？ | `npc_op` |
| 立即数如何解码 | I、S、B、U、J 型的位序不同 | `sext_op` |

Controller 的输入是指令编码（`opcode`、`funct3`、`funct7`），输出是上述控制信号。控制信号取值表就是 Controller 的真值表/译码规格。

### 2.5 做表时的思考顺序

每遇到一条指令，按以下问题逐项判断即可：

1. 读哪些源寄存器，写哪个目的寄存器？
2. 是否需要立即数，属于什么编码类型？
3. ALU 的 A、B 分别是什么，ALU 要做什么？
4. 是否读/写数据存储器，地址与写数据来自哪里？
5. 写回数据来自哪里，是否写回？
6. 下一条 PC 是 `PC+4`、条件分支目标还是跳转目标？
7. 上述每个选择在控制表中对应哪个控制信号取值？

## 5. 数据通路部件与字段

| 单元 | 部件 | 关键输入 | 职责 |
| --- | --- | --- | --- |
| 取指 | `PC` | `npc` | 保存当前指令地址 |
| 取指 | `NPC` | `pc`、`offset`、`br` | 产生 `PC + 4`、条件分支目标或跳转目标 |
| 译码 | `RF` | `rR1`、`rR2`、`wR`、`wD` | 读源寄存器、写回目的寄存器 |
| 译码 | `SEXT`/`EXT` | `imm` | 按指令类型扩展立即数 |
| 执行 | `ALU` | `A`、`B` | 算术、逻辑、比较和地址计算 |
| 访存 | `MREQ` | `ram_addr`、`ram_wdata` | 向数据存储器发起读写请求 |
| 访存 | `MEXT` | `din`、`byte_offs` | 对读出的字节/半字/字进行扩展 |

常用连接关系：

- 指令存储器：`PC.pc -> IROM.adr`，`IROM.inst -> Controller` 及各指令字段输入。
- 取指更新：`NPC.npc -> PC.npc`，`PC.pc -> NPC.pc`。
- 寄存器读：`IN.inst` 的源寄存器字段分别接 `RF.rR1`、`RF.rR2`。
- 执行：`RF.rD1 -> ALU.A`；`RF.rD2` 或 `SEXT.ext -> ALU.B`。
- 访存：`ALU.C -> MREQ.ram_addr`；读数据经 `MEXT` 后可写回 `RF.wD`。
- 写回：`ALU.C`、`SEXT.ext`、`MEXT.ext` 和 `NPC.pc4` 是 `RF.wD` 的候选来源。

控制信号含义：

| 信号 | 类别 | 作用 |
| --- | --- | --- |
| `npc_op` | 操作选择 | 选择 `PC4`、条件 `BRANCH` 或 `JUMP` 的下一条 PC 计算方式 |
| `rf_we` | 操作选择 | 使能寄存器堆写回 |
| `rf_wsel` | 多路选择 | 选择 `ALU`、`EXT`、`RAM` 或 `PC4` 写回数据 |
| `sext_op` | 操作选择 | 选择 I/S/B/U/J 等立即数拼接和扩展方式 |
| `alu_op` | 操作选择 | 选择 ALU 的算术、逻辑或比较操作 |
| `alub_sel` | 多路选择 | 选择 `RF.rD2` 或 `SEXT.ext` 作为 ALU 的 B 输入 |
| `ram_rop` | 操作选择 | 选择不读、字读或其他读数据扩展方式 |

## 8. 扩展其余指令时的规则

### R 型算术/逻辑指令

典型指令：`add`、`sub`、`and`、`or`、`xor`、`sll`、`srl`、`sra`、`slt`、`sltu`。

- 数据通路：`rs1 -> RF.rR1`、`rs2 -> RF.rR2`、`rd -> RF.wR`、`RF.rD1 -> ALU.A`、`RF.rD2 -> ALU.B`、`ALU.C -> RF.wD`。
- 典型控制：`npc_op=PC4`、`rf_we=1`、`rf_wsel=WB_ALU`、`alub_sel=SEL_RS2`、`ram_rop=0`。
- 区分指令的关键是 `alu_op`，以及编码冲突时的 `funct7`。

### I 型立即数运算与移位指令

典型指令：`addi`、`andi`、`ori`、`xori`、`slti`、`sltiu`、`slli`、`srli`、`srai`。

- 与 `addi` 行相同的骨架：B 端选择立即数，结果从 ALU 写回。
- 依据指令决定 `alu_op`；`srai` 与 `srli` 的 `funct3` 相同，必须结合 `funct7` 区分。

### Load 指令

典型指令：`lb`、`lbu`、`lh`、`lhu`、`lw`。

- 地址计算固定为 `rs1 + sext(offset)`，因此 `alu_op=ADD`、`alub_sel=SEL_EXT`。
- 写回来源固定为 `WB_RAM`，但 `ram_rop`/MEXT 操作必须按字节、半字、字及有无符号扩展分别编码。

### Store 指令

典型指令：`sb`、`sh`、`sw`。

- 地址：`rs1 + sext(offset)`；写数据来自 `rs2`。
- 不写回寄存器，`rf_we=0`。
- 模板的示例只覆盖读访存；实现 store 时应检查基础工程是否还定义了 `ram_wop`、写使能或字节写使能，并把该信号纳入数据通路图与控制器。不能仅把 `ram_rop` 填为 `0` 就视为已完成写存储。

### 分支和跳转指令

- `beq/bne/blt/bge/bltu/bgeu`：两个源寄存器进入 ALU 比较，`npc_op=BRANCH`，不写回 RF；立即数采用 B 型拼接。
- `jal`：`npc_op=JUMP`，立即数采用 J 型拼接，`PC+4` 写回 `rd`。
- `jalr`：需同时计算跳转目标与 `PC+4` 写回；先查看基础工程 NPC/ALU 接口是否已支持“寄存器 + 立即数”的目标地址和最低位清零，再补充必要的选择信号。
- `auipc`：写回 `PC + (imm << 12)`；检查工程中该运算在 ALU 还是 NPC/专用通路实现，并据此扩展数据通路和写回选择。

## 9. miniLA 的差异提醒

- miniLA 模板中的源寄存器字段通常为 `rj=inst[9:5]`、`rk/rd=inst[4:0]`，与 miniRV 的 `rs1/rs2/rd` 位段不同。
- 模板示例为 `addi.w`、`ori`、`slli.w`、`lu12i.w`、`ld.w`、`beq`、`bne`、`b`。
- miniLA 立即数控制名为 `SIGN_12`、`UNSIGN_12`、`UNSIGN_5`、`SIGN_20`、`SIGN_16`、`SIGN_26` 等，应按模板命名填写。
- 不要将 miniRV 的 `jal` 直接套到 miniLA；miniLA 示例的无条件跳转是 `b`，其他跳转（如 `jirl`、`bl`）要依据其编码和工程接口单独补充。
