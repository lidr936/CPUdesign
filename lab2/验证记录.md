## Cache-on C_TEST 操作清单

下一步在自建 `miniRV_pipeline_axi` 工程中启用 Cache 后，按以下顺序复跑 C_TEST：

1. 在 Vivado 的 IP Catalog 新建 `Block Memory Generator`，模块名为 `blk_mem_gen_1`；
   配置为 Native、Single Port RAM、读写宽度 151 bit、深度 64、`WRITE_FIRST`、
   Always Enabled、无 Byte Write Enable、无输出寄存器、无初始化文件。生成 Output
   Products 后，确认 `blk_mem_gen_1.xci` 出现在 Design Sources。一个 IP 模块即可被
   `ICache` 和 `DCache` 分别实例化。
2. 在 `src/rtl/defines.vh` 启用 `ENABLE_ICACHE` 和 `ENABLE_DCACHE`；保存后确认
   `ICache.v`、`DCache.v` 和 `blk_mem_gen_1.xci` 都在工程源文件中。
3. 右键 `bram_axi` 并 Re-customize IP，在 Memory Initialization 中启用 COE 文件，
   先选择 `c_test_rv_stu/0_uart_test/main.coe`，再 Generate Output Products。
4. Reset Runs 后依次运行 Synthesis、Implementation 和 Generate Bitstream，下载新生成
   的 bitstream。串口仍为 115200、8N1、无流控；自建 bitstream 不发送 `.bin`。
5. C_TEST0 验证启动文本、字符回显、LED 和数码管；若程序立即结束，先将任一拨码开关
   置 1 再复位。通过后按步骤 3 至 4 依次换成 `1_formatIO_test/main.coe` 与
   `2_sort_test/main.coe`，每次都重新生成 bitstream。

完成 Cache-on C_TEST0、1、2 后，进入 DDR 配置与 `3_ddr_test`，再进行 CoreMark 或
LLAMA2 的最终下板验证。

## Cache-on C_TEST0 串口错位修复

验证日期：2026-07-31。Cache-on bitstream 上，连续输入 `A` 后出现多次空
`Input received:`；随后连续按回车才依次输出 `A`。该 bitstream 不通过 C_TEST0。

根因是 `axi_master` 将外设非缓存读仍发成四拍 AXI burst。轮询 UART 状态
`0xFFFF3008` 的第三拍会因 UARTLite 低 4 位地址译码回绕为 RX FIFO 读，从而提前取走
输入字节。

- 新增 `tests/axi_master_handshake_tb.v` 的 MMIO 单拍断言；旧 RTL 实测断言失败。
- 修复 `axi_master.v` 后，Verilator 回归通过：MMIO 为 `ARLEN=0`，普通 Cache-on 与
  Cache-off 请求仍为四拍 Cache line 读。
- 待重新综合、实现、烧录该修复后的 Cache-on bitstream，再从 C_TEST0 验证单个 `A`
  是否立即且仅回显一个 `A`。
