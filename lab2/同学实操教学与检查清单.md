# 实验二实操教学与检查清单

适用对象：负责 Vivado、I/O、C_TEST 和 EGO1 下板的同学。

硬件工程唯一入口是 `lab2/miniRV_pipeline_axi/miniRV.xpr`。它完整继承 Lab1
Vivado 工程结构，并已用 Lab2 最终流水线 AXI SoC 的 `src/` 覆盖源码。自动
RTL/Trace 已完成；本清单处理课程要求且必须在 Vivado/开发板上完成的部分。
课程对应章节：

- [Lab2-B 总线实现](https://cpu-design.p.cs-lab.top/lab2-B/4-bus_impl/)
- [Lab2-B I/O 接口实现](https://cpu-design.p.cs-lab.top/lab2-B/6-ioitf_impl/)
- [Lab2-B I/O 编程与下板](https://cpu-design.p.cs-lab.top/lab2-B/5-ioupg/)

不要直接修改 `lab1/` 或另建 Vivado 工程。所有手动新增 RTL、COE、约束和 IP 都
放进 `lab2/miniRV_pipeline_axi/`。`integrated_soc/miniRV_pipeline_axi` 是已通过
Trace 的源码镜像；需要回归 Trace 时，先将本工程的 `src/` 同步覆盖该镜像，再运行
`lab2/tools/sync_integrated_trace_sources.sh`。

## 1. 创建时钟与主存 IP

### 1.1 时钟

- [ ] 工程已携带 Lab1 的 `clk_wiz_0` IP。先确认它能正常生成；仅在 IP 升级或缺失时，
  才通过 `IP Catalog` 重新生成同名 `clk_wiz_0`。
- [ ] 端口必须包含 `clk_in1`、`clk_out1`、`locked`，与 `miniRV_SoC.v` 一致。
- [ ] 设置 CPU 时钟为 50 MHz 或更高；若后续改频率，UART 的 AXI 时钟频率也必须同步修改。

### 1.2 AXI 主存

- [ ] `IP Catalog` 搜索 `block`，选择 **Block Memory Generator**。
- [ ] Component Name 设为 `bram_axi`。
- [ ] Basic 页：Interface Type 选 **AXI4**；Memory Type 选 **Simple Dual Port RAM**。
- [ ] Port A Options 页：Port A Width = **32**，Port A Depth = **38400**。
- [ ] Other Options 页：勾选 **Load init File**，先选择 `src/coe/lw.coe`；勾选
  **Fill Remaining Memory Locations**；取消 **Enable Safety Circuit**。
- [ ] 生成 IP 后，确认模块名为 `bram_axi`，AXI 端口为 `s_axi_*`。

**通过标准：** IP 生成成功且端口与课程页面的 `bram_axi` 实例一致。首次功能仿真
用 `lw.coe`；验证写通道时，改用由 `sw.bin` 生成的 COE。

## 3. 创建 I/O IP

先创建协议转换器，后续每个 AXI4-Lite 外设使用一个转换器或按课程模板复用相应
实例。

- [ ] `IP Catalog` 搜索 `protocol`，创建 **AXI Protocol Converter**，保持默认
  参数。命名可为 `axi_protocol_converter_0`、`..._1` 等。
- [ ] `IP Catalog` 搜索 `gpio`，创建 AXI GPIO：
  - Switch：32-bit，**All Inputs**。
  - LED：16-bit，**All Outputs**。
  - 数码管：按 `dig_en/dig_seg/dig_seg1` 的封装需要设置输出位宽；保持课程模板
    的引脚语义。
  - Timer：勾选 **Enable Dual Channel**，两个通道均 **All Inputs**、32-bit；
    `GPIO` 接 `timer[31:0]`，`GPIO2` 接 `timer[63:32]`。
- [ ] `IP Catalog` 搜索 `uart`，创建 **AXI Uartlite**：AXI CLK Frequency = 当前
  CPU 时钟 MHz（50 MHz 时填 50），Baud Rate = **115200**，Data Bits = 8，No Parity。
- [ ] 新建 `timer_wrap.v`：实现复位清零、每拍加一的 64-bit `timer`，把它接到
  Timer GPIO 的两个输入通道，并经 Protocol Converter 暴露 AXI4 Slave。
- [ ] 新建 `uart_wrap.v`：按课程 `timer_wrap` 的 AXI4 -> AXI4-Lite 转换方式接
  Uartlite，并把 `tx/rx` 接到顶层端口。
- [ ] 新建/补全 `switch_wrap.v`、`led_wrap.v`、`digled_wrap.v`：各自经 Protocol
  Converter 接 AXI GPIO；顶层接到 `sw/led/dig_en/dig_seg/dig_seg1`。

**通过标准：** 每个 wrapper 都有一组 AXI4 Slave 端口，外部引脚只由对应 wrapper
驱动；Timer 两个寄存器偏移分别是 `+0x0` 和 `+0x8`。

## 4. AXI Crossbar 与地址映射

- [ ] `IP Catalog` 搜索 `cross`，创建 **AXI Crossbar**，Component Name 设为
  `axi_crossbar_0`。
- [ ] Slave Interfaces 数量设为 **1**，Master Interfaces 数量设为 **6**。
- [ ] 在 Address 页设置以下地址。主存范围按 `bram_axi` 实际容量配置；五个外设
  保持下表基址不变。

| Master | 从设备 | 基址 | 必需偏移 |
| --- | --- | --- | --- |
| M00 | `bram_axi` | `0x0000_0000` | 程序/数据主存 |
| M01 | Switch | `0xFFFF_0000` | 只读 |
| M02 | LED | `0xFFFF_1000` | 写 |
| M03 | 数码管 | `0xFFFF_2000` | 写 |
| M04 | UART | `0xFFFF_3000` | RX `+0x0`、TX `+0x4`、STAT `+0x8`、CTRL `+0xC` |
| M05 | Timer | `0xFFFF_4000` | low `+0x0`、high `+0x8` |

- [ ] 修改 `miniRV_SoC.v` 的非 `RUN_TRACE` 分支：删除当前的 AXI 零响应
  `assign`，实例化 `axi_crossbar_0`。S00 接 `U_cpu` 的 AXI 主机，M00-M05 按表接
  `bram_axi` 与五个 wrapper。
- [ ] `RUN_TRACE` 分支保留现有 `bram_axi` 直连，不经过 Crossbar。
- [ ] 在 `miniRV_SoC.v` 的 ``ifndef RUN_TRACE`` 分支实例化五个 wrapper，并接
  板级 `sw/led/dig_en/dig_seg/dig_seg1/rx/tx`。

**通过标准：** Elaborate Design 中只有一个 AXI Master（CPU），其 S00 经 Crossbar
可到达六个从设备；没有多驱动 AXI ready/valid 信号。

## 常见卡点

| 现象 | 先检查什么 |
| --- | --- |
| Trace 过了但 Vivado 报 IP 缺失 | 是否创建了 `clk_wiz_0`、`bram_axi`、`blk_mem_gen_1`、Crossbar、GPIO/Uartlite/Converter |
| Cache-on 黑盒或仿真读错 | `blk_mem_gen_1` 的模块名、64 x 151、同步读、Write First |
| 串口没有输出 | Uartlite 时钟频率是否等于 CPU，是否为 115200/无流控，TX 是否接顶层/约束 |
| I/O 程序卡住 | Crossbar 地址是否和表中一致，UART TX 是否先检查 STAT[3]，Timer 是否双通道 |
| 只能运行 Trace | `RUN_TRACE` 是否被错误用于硬件构建；硬件必须走 Crossbar |
| 读写 AXI 卡死 | AW、W、B 不能省；检查 `valid && ready` 握手，不要假设 AW/W 同拍 |
