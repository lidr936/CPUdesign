## 路线 A：先做流水线 CPU

适合目标：先把 CPU 主体从单周期改成五级流水，通过 Basic Trace，再与 SoC 合并。

### A1. 复制基线工程

从实验一工程复制出 `lab2/pipeline_cpu/miniRV_basic`，保留 RTL、COE、Vivado 工程和必要 IP，但后续提交仍应只提交源文件与报告。

### A2. 设计五级流水寄存器

建议先按经典五级划分：

- IF：发出取指请求，维护 PC。
- ID：译码、读寄存器、立即数扩展、生成控制信号。
- EX：ALU、分支条件判断、乘除启动和等待。
- MEM：数据访存请求、访存响应处理。
- WB：寄存器写回、Trace 调试信号输出。

需要新增或重构的寄存器组：

- IF/ID：`pc`、`inst`、有效位。
- ID/EX：源操作数、立即数、`rs1/rs2/rd`、控制信号、PC、有效位。
- EX/MEM：ALU 结果、store 数据、访存控制、写回控制、rd、PC、有效位。
- MEM/WB：load 数据或 ALU 结果、写回控制、rd、PC、有效位。

### A3. 先实现理想流水线

限制测试程序：

- 不包含访存。
- 不包含乘除法。
- 不包含分支跳转。
- 不包含相邻数据相关。

目标是先验证 PC 推进、流水寄存器传递和 WB 写回不错位。

### A4. 增加冒险检测

在 ID 阶段检测 RAW 冒险：

- EX 阶段将写回的 `rd` 与 ID 阶段 `rs1/rs2` 冲突。
- MEM 阶段将写回的 `rd` 与 ID 阶段 `rs1/rs2` 冲突。
- WB 阶段将写回的 `rd` 与 ID 阶段 `rs1/rs2` 冲突。

必须排除：

- 当前指令未读取该源寄存器。
- 后级指令不写寄存器。
- `rd == 0`。

### A5. 暂停与冲刷

暂停信号用于：

- load-use 数据无法及时前递。
- 访存指令等待 `daccess_rvalid` 或 `daccess_wresp`。
- 乘除法等待 `busy` 结束。

冲刷信号用于：

- 分支/跳转预测失败。
- `jal`、`jalr`、branch taken 等实际改变 PC 的指令。

实现时要区分“暂停保持”和“冲刷插入 NOP”，两者优先级需要明确。通常异常修正 PC/冲刷优先级高于普通推进，但与正在等待的访存/乘除完成信号要谨慎配合。

### A6. 数据前递

优先实现以下前递：

- EX 结果前递给 ID/EX 操作数选择。
- MEM 阶段 ALU 结果前递。
- WB 写回数据前递。

Load-use 冒险即使有前递也往往需要至少暂停，等 load 数据可用后再前递。

### A7. Trace 对齐

Basic Trace 依赖 `debug_wb_*` 信号。流水线后必须保证：

- `debug_wb_pc` 是 WB 阶段正在提交的指令 PC。
- `debug_wb_rf_we` 只在真实提交写寄存器时有效。
- `debug_wb_rf_wR` 是 WB 阶段目标寄存器。
- `debug_wb_rf_wD` 是 WB 阶段真实写回数据。
- 被冲刷的指令不能产生写回和 Trace 提交。

## 路线 B：再做 AXI SoC

适合目标：先把实验一 CPU 接到 AXI 总线、Cache、主存和外设，得到可下板的单周期 SoC，再与流水线 CPU 集成。

### B1. 复制基线工程

从实验一工程复制出 `lab2/axi_soc/miniRV_basic`，用于 SoC 改造。

### B2. 集成 Cache

集成 ICache 和 DCache 后，CPU 侧不再直接访问 IROM/DRAM，而是：

```text
CPU 取指/访存接口 -> ICache/DCache -> axi_master
```

如果 Cache 模块暂时不可用，可先保留禁用 Cache 的路径跑通 AXI Trace。

### B3. 实现 `axi_master`

`axi_master` 负责仲裁请求并驱动 AXI4：

- ICache 读请求。
- DCache 读请求。
- DCache 写请求。

建议先实现简单串行状态机：

- 空闲态按优先级接收一个请求。
- 读请求：发 AR，等 R 数据，拼接 128 位 cache line 后返回。
- 写请求：发 AW/W，等 B 响应后完成。
- 同时只处理一个事务。

优先级按指导书：

```text
DCache 写 > DCache 读 > ICache 读
```

### B4. 主存与总线桥

主存使用 `bram_axi`。多个从设备需要通过 AXI Crossbar 或等价总线桥按地址分发：

- 主存地址空间。
- SW/LED/数码管/UART/计时器外设地址空间。

Trace 模式下可保留直接接 `bram_axi` 的路径；非 Trace 下接 Crossbar 和外设。

### B5. 外设 I/O

最低实现：

- 拨码开关：只读 AXI GPIO。
- LED：写 AXI GPIO。
- 数码管：写 AXI GPIO。
- UART：AXI Uartlite，波特率 115200，输入时钟与 CPU 时钟一致。
- 计时器：64 位计数器，通过 AXI GPIO 暴露低 32 位和高 32 位。

### B6. C_TEST 与下板

先用课程提供的 `lab2_IOtest_miniRV_ego1.bit` 验证 C_TEST 程序和串口下载流程，再把程序导入自己的 SoC。

miniRV/EGO1 的优先附件：

- `c_test_rv_stu.tar.gz`
- `lab2_IOtest_miniRV_ego1.bit`

## 推荐推进顺序

建议先按“可验证闭环”推进：

1. 建立 `lab2/pipeline_cpu` 工程副本。
2. 做理想流水线，只跑简单 COE 仿真。
3. 补暂停/冲刷/前递，通过 Basic Trace。
4. 建立 `lab2/axi_soc` 工程副本。
5. 禁用 Cache 跑通最小 AXI SoC。
6. 加 Cache，通过 AXI Trace。
7. 加 5 个外设，跑 C_TEST。
8. 合并流水线 CPU 与 SoC。
9. 跑 CoreMark，记录频率、用时、时序和资源。

## 主要风险

- 流水线写回信号和 PC 错位，导致 Trace 失败但单步仿真不容易看出。
- 分支冲刷与暂停同时出现时优先级处理错误。
- Load-use 冒险误判或漏判。
- 乘除法 `start` 未保持单周期，或 `busy` 期间重复启动。
- AXI 写通道 AW/W 接收顺序不确定，状态机不能假定两者同拍完成。
- Cache line 为 128 位，AXI 读数据为 32 位时需要正确拼接和 `rlast` 判断。
- 提高 CPU 频率后忘记同步修改 UART IP 输入频率和 CoreMark `MHZ`。
