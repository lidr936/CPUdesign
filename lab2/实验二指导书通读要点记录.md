# 实验二指导书通读要点记录

## 总目标

实验二最终目标是在实验一完整单周期 CPU 的基础上，完成流水线 CPU 与 SoC 的设计、验证和下板。课程站点把实验二分成两条线：

- `lab2-A`：把完整单周期 CPU 改造成至少五级流水线 CPU，处理数据冒险和控制冒险，通过 Basic Trace。
- `lab2-B`：实现支持 AXI 总线、Cache、主存和 I/O 外设的 SoC，通过 AXI Trace，并完成 CoreMark 或 LLAMA2 下板测试。

两条线最后需要合并：流水线 CPU 集成到 SoC，使用 AXI Trace 验证流水线 SoC，并在 FPGA 上运行 CoreMark 或 LLAMA2。

## Lab2-A：流水线 CPU

### 实验要求

- 至少实现五级流水线。
- 支持 miniRV 或 miniLA 的全部指令；本工作区按 miniRV 继续。
- 从单周期 CPU 数据通路出发，先设计理想流水线 CPU。
- 使用静态分支预测解决控制冒险，课程基础要求是默认预测不跳转。
- 使用流水线暂停和数据前递解决数据冒险。
- 通过 Basic Trace。
- 流水线 SoC 频率不低于 50MHz；单周期 SoC 频率不低于 25MHz。
- 下板检查时不能有时序违例。

### 推荐实施顺序

1. 复制实验一完整单周期 CPU 工程及代码到新目录。
2. 划分单周期数据通路，在模板工程上实现理想流水线 CPU。
3. 使用无指令相关、无访存、无乘除法的简单程序做 Vivado 功能仿真。
4. 增加冒险检测逻辑，并为分支跳转修改取指逻辑。
5. 实现默认不跳转的静态分支预测，预测失败时清空分支后面的流水级并用正确 PC 重新取指。
6. 实现暂停法，覆盖数据冒险、访存指令和乘除法指令。
7. 实现数据前递，减少可前递场景下的暂停。
8. 使用 Basic Trace 验证流水线 CPU。
9. 与 SoC 侧集成后运行 AXI Trace 和下板测试。

### 取指逻辑变化

理想流水线要求取回一条指令时立即发出下一条取指请求。指导书给出的核心思路是：

```verilog
assign ifetch_req = first_req | ifetch_valid;
assign ifetch_addr = pc;
```

实验一当前 `cpu_core.v` 的取指节奏是以 `inst_finished_r` 为基础的单周期/多周期完成模型：

```verilog
assign ifetch_req = first_req | inst_finished_r;
```

实验二需要把“指令完成后再取下一条”的模型改成流水线模型：IF 阶段、ID 阶段、EX 阶段、MEM 阶段、WB 阶段同时有不同指令推进。

### 流水寄存器

把单周期数据通路切成多级后，必须把跨级使用的控制信号和数据一起写入流水寄存器。尤其要注意写回相关信号：

- 目标寄存器号 `rd`
- 写使能
- 写回数据选择
- 当前指令 PC
- 访存读写控制
- ALU/乘除控制

如果只把数据结果传到后级，而目标寄存器号仍使用前级当前指令，会把上一条指令的结果写到下一条指令的寄存器里。

### 数据冒险检测

指导书按 RAW 冒险列出三类检测：

- 情形 A：`ID/EX.rd == ID.rs1` 或 `ID/EX.rd == ID.rs2`
- 情形 B：`EX/MEM.rd == ID.rs1` 或 `EX/MEM.rd == ID.rs2`
- 情形 C：`MEM/WB.rd == ID.rs1` 或 `MEM/WB.rd == ID.rs2`

检测时需要同时判断：

- 后级指令确实会写寄存器。
- 当前 ID 阶段指令确实读取对应源寄存器。
- `rd != x0`，因为零号寄存器不可写，不构成 RAW 冒险。

参考判断形式：

```verilog
wire rs1_id_wb_hazard = (wb_rd == id_rs1) & wb_we & id_rf1 & (wb_rd != 5'h0);
wire rs2_id_wb_hazard = (wb_rd == id_rs2) & wb_we & id_rf2 & (wb_rd != 5'h0);
```

### 暂停法

暂停法的本质是暂停相关寄存器更新：

- PC 保持不变。
- IF/ID、ID/EX、EX/MEM、MEM/WB 等流水寄存器按需要保持不变。

访存指令和乘除法指令也要靠暂停延长执行过程：

- 访存：发出 1 个周期有效的 `daccess_ren` 或 `daccess_wen`，暂停前级，直到 `daccess_valid` 或 `daccess_wresp` 有效。
- 乘除：发出 1 个周期有效的 `start`，暂停前级，直到 `busy` 从高变低。

### 数据前递

前递方向主要是从 EX/MEM/WB 后级把结果送回 ID 或 EX 的操作数选择逻辑。可前递的 ALU 结果不必等待写回阶段。Load-use 这类数据必须等访存结果返回，通常仍需要暂停配合。

### 控制冒险

课程基础要求是默认预测不跳转。分支指令在 EX 阶段得到真实结果后：

- 预测正确：继续推进。
- 预测失败：清空分支后已进入流水线的错误指令，并把 PC 修正到真实目标。

## Lab2-B：SoC、AXI、I/O

### 实验要求

- 为 CPU 实现 ICache 和 DCache。
- 使用状态机实现支持 AXI 协议的总线控制器 `axi_master`。
- 为 SoC 添加总线桥和主存模块。
- 完成 I/O 接口测试程序，并在 SoC 上下板测试。
- 至少实现 5 个外设：拨码开关、LED、数码管、UART、计时器。
- 使单周期 CPU 及 SoC 通过 AXI Trace。
- 与流水线 CPU 集成后，继续通过 AXI Trace 和 CoreMark/LLAMA2 下板。

### 推荐实施顺序

1. 复制单周期 CPU 工程，在副本上开发总线控制器和 I/O 接口。
2. 集成计算机组成原理实验 3 的 ICache、DCache。
3. 用状态机实现 `axi_master`，添加总线桥和主存 IP。
4. 完成 C_TEST 测试程序，用课程提供的 SoC bitstream 先验证 C 代码和串口下载流程。
5. 在自己的 SoC 中实现拨码开关、LED、数码管、UART、计时器 I/O 接口。
6. 使用 AXI Trace 验证单周期 SoC。
7. 集成流水线 CPU，验证流水线 SoC。
8. 下板运行 CoreMark 或 LLAMA2，并尝试性能优化。

### SoC 架构

指导书中的结构是：

```text
cpu_core
  -> ICache / DCache
  -> axi_master
  -> bridge / AXI Crossbar
  -> bram_axi / 外设 I/O
```

`axi_master` 接收 Cache 侧访存请求，转换为 AXI4 读写事务。bridge 根据地址把请求送到主存或外设。

### AXI4 重点

AXI4 基于 `ready`-`valid` 握手：只有 `ready` 和 `valid` 同时为高时，信息才在时钟上升沿完成传输。

AXI4 有 5 个独立通道：

- `AR`：读地址
- `R`：读数据
- `AW`：写地址
- `W`：写数据
- `B`：写响应

课程简化建议：

- `rready` 和 `bready` 可以复位后一直置 1。
- `rresp` 和 `bresp` 可以忽略。
- `arid`、`awid`、`wid` 可用常量驱动。
- 写请求只有 AW 和 W 都被从设备接收后，才算请求被接收并处理。

### Cache 侧接口

`axi_master` 同时面向 ICache 和 DCache：

- ICache：读请求接口。
- DCache：读请求接口和写请求接口。

指导书建议优先级：

```text
DCache 写请求 > DCache 读请求 > ICache 读请求
```

如果只做基础总线功能，可在多个请求同时存在时只处理最高优先级请求，先保证功能正确。

### 外设地址

| 外设 | 地址 | 属性 | 功能 |
| --- | --- | --- | --- |
| 拨码开关 | `0xFFFF_0000` | 只读 | 外部输入 |
| LED | `0xFFFF_1000` | 写 | 显示数据 |
| 数码管 | `0xFFFF_2000` | 写 | 显示数据 |
| UART RX FIFO | `0xFFFF_3000` | 只读 | 接收字符 |
| UART TX FIFO | `0xFFFF_3004` | 写 | 发送字符 |
| UART 状态寄存器 | `0xFFFF_3008` | 读 | FIFO 状态 |
| UART 控制寄存器 | `0xFFFF_300C` | 写 | 初始化和控制 |
| 计时器低 32 位 | `0xFFFF_4000` | 只读 | 读取 `timer[31:0]` |
| 计时器高 32 位 | `0xFFFF_4008` | 只读 | 读取 `timer[63:32]` |

## 验证要求

- 流水线 CPU：先简单程序 Vivado 仿真，再 Basic Trace。
- 单周期 AXI SoC：建议先禁用 Cache 跑 AXI Trace，通过后再启用 Cache。
- 流水线 AXI SoC：集成后跑 AXI Trace。
- 下板：CoreMark 或 LLAMA2。
- 改 CPU 频率后，需要同步修改 CoreMark 的 `MHZ` 参数和 UART IP 的输入时钟频率。
