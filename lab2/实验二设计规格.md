# 实验二流水线 CPU 与 SoC 设计规格

## 目标

在已通过 Basic Trace 的 miniRV 单周期 CPU 基线之上，完成实验二所有可在工作区内实现和验证的内容：五级流水线 CPU、AXI SoC、Cache/主存/I-O 外设，以及流水线 CPU 与 SoC 的集成。Vivado 图形操作、FPGA 下板、串口下载和截图采集作为用户手动验收项，提供可执行步骤和验收标准。

## 范围与验收

- Lab2-A 第 1 至第 6 步：独立五级流水线 miniRV CPU，支持 Lab1 已实现的 36 条指令，默认预测不跳转，具有暂停、冲刷和前递逻辑，保持 `debug_wb_*` 提交接口，并具备 Basic Trace 验证入口。
- Lab2-A 第 7 步：流水线 CPU 接入 AXI SoC，具备 AXI Trace 验证入口。
- Lab2-B：ICache/DCache 连接、`axi_master`、主存/桥接、拨码开关、LED、数码管、UART、64 位计时器，以及 C_TEST/AXI Trace 的准备脚本和说明。
- 自动化验证至少覆盖：RTL 文件集合与接口静态检查、关键流水线冒险场景、AXI 主控握手状态、外设地址映射、工程/Trace 源码同步。
- 不宣称未在当前环境执行的 Vivado、Basic Trace、AXI Trace、上板、CoreMark 或 LLAMA2 已通过；这些项必须记录为用户手动执行并保留命令、预期现象和证据位置。

## 非范围

- 不修改原始 `lab1/miniRV_basic_ego1/miniRV_basic` 作为实现目标。
- 不提交 Vivado 生成目录、IP 生成物、bitstream 或超过课程要求的工程缓存。
- 不自行伪造 Vivado 波形、时序、功耗或 FPGA 实验结果。

## 实施架构

工作目录按功能隔离：

```text
lab2/
  pipeline_cpu/       # Lab2-A 独立工程与 RTL
  axi_soc/            # 单周期 AXI SoC 独立工程与 RTL
  integrated_soc/     # 流水线核接入 AXI SoC 的最终工程
  assets/             # 课程提供的可再分发附件
  tests/              # 可自动化 Verilog/Python 静态与行为检查
  notes/              # Trace、Vivado 和下板的执行记录
```

流水线核保持顶层 `cpu_core` 对外取指、数据访存和 `debug_wb_*` 契约不变。内部按 IF、ID、EX、MEM、WB 五级划分，并用 IF/ID、ID/EX、EX/MEM、MEM/WB 有效位寄存器控制推进。分支在 EX 判定；预测失败时修正 PC 并冲刷错误路径。暂停优先保证访存和乘除法事务完整，数据前递仅对已经产生的结果生效，load-use 仍可暂停。

SoC 采用 CPU -> ICache/DCache -> `axi_master` -> AXI bridge -> BRAM/外设 的路径。`axi_master` 同一时刻只处理一个事务，请求优先级为 DCache 写、DCache 读、ICache 读。外设地址以课程规定的 `0xFFFF_0000` 至 `0xFFFF_4008` 为准。

## 推进顺序

1. 在隔离工作区从 Lab1 基线建立三个实验二工程副本和可重复同步脚本。
2. 完成并验证理想流水线，随后加入控制冒险、暂停、前递和 Trace 提交对齐。
3. 完成单周期 AXI SoC：先无 Cache 通路，再 Cache 通路、主存、桥接和五类外设。
4. 用流水线 CPU 替换 SoC 内核，复用已验证的 Cache/AXI/I-O 设计。
5. 运行可用的本机验证；生成 Vivado、Basic Trace、AXI Trace、C_TEST、下板和性能测试的手动验收清单。

## 风险控制

- 流水寄存器必须同时携带数据、控制、目标寄存器、PC 和有效位，冲刷指令不得提交 Trace。
- AXI 写地址和写数据通道独立握手，状态机不可假设二者同周期完成。
- Cache 与外设地址空间必须在集成前通过地址映射检查。
- 任何不能在当前环境运行的工具验证，都以脚本可启动、输入输出路径正确为最低可证实结果，并明确标记为待用户执行。
